# 1MM-ADR-0068 · Human-readable references keep the `PREFIX-n` pattern

## Context

Staff and members quote references: a report, a safety escalation, a support ticket, an appeal, a
refund, a privacy request, a legal hold, a security incident. Entity keys are UUID v7
([1MM-ADR-0011](1MM-ADR-0011-UUID-V7-PRIMARY-KEYS.md)), which nobody can read out on a call. The
schema generates short references from sequences; several boards showed a different form with a
year in it [OD-40].

## Decision

1. References keep the existing **`PREFIX-n`** pattern, with the prefixes `R-`, `S-`, `W-`,
   `SR-`, `SE-`, `A-`, `RF-`, `PR-`, `LH-`, `SI-` and `J-` [OD-40].
2. The reference is generated by the database (a sequence default on a unique `public_ref`
   column, for example `'SE-' || nextval(...)`) [SQL].
3. Board forms with a year in the reference are board fixes [OD-40].
4. Invoice numbers keep their own format, `1MM-YYYY-Rnnnnn` [OD-40].

## Alternatives considered

- **Year-based references**, as some boards showed. Not chosen: the existing schema pattern
  stands and the boards change [OD-40].

**Analysis:** exposing the UUID is unreadable; a year-based form needs a per-year counter reset
and longer strings for no lookup benefit.

## Consequences

- Easier: one pattern to validate, search and print; the admin search box can recognise a
  reference by its prefix.
- Harder: sequence numbers reveal volume and are guessable. A reference is therefore an
  identifier, never an authorisation: looking one up always passes the normal permission and
  scope checks, and an out-of-scope row answers `404`
  ([1MM-STD-13 §2.2](../standards/1MM-STD-13-ERROR-CODES.md)). **Analysis.**
- Harder: sequences leave gaps on rollback; no code or copy may assume consecutive numbers.

## How it is applied

- Clients display the `public_ref` the API returns; no client builds or parses a reference
  beyond prefix recognition in search.
- Naming of the columns and sequences follows
  [1MM-STD-14 §4.2](../standards/1MM-STD-14-CODING-CONVENTIONS.md) and
  [1MM-DB-03](../database/1MM-DB-03-SQL-STRUCTURE.md).
- Checks: database tests that each reference column is unique and generated; API tests that a
  lookup by reference respects scope; a review item that templates show the reference from data.

## Revisit when

A regulator or payment provider requires a reference format, or volume disclosure through
sequence numbers becomes a concern (then switch to a non-sequential short code by migration).
