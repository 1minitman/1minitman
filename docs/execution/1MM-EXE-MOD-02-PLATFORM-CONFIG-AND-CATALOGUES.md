This is the module that makes the owner's rule "every UI element, component or piece of text is
supported by the API and managed by the admin, including the admin console's own constants" true in
practice. Open it when you add a limit, a flag, an option list, a label or a locale anywhere in the
product, when you touch the first call every client makes (`GET /v1/config`), or when you build the
admin Platform pages, the catalogue pages or the translation pages.

## 1. Outcome

When this module is done:

- **A member** opens the app and, before anything else, the app knows whether it must update, whether
  the service is under maintenance, which features are on, which limits apply and which languages are
  offered. The member can pick English, Naijá or French before signing up (OB2), and every label,
  option and message on later screens comes from a catalogue that staff can change.
- **A website visitor** can switch language (W04) and theme (W05), and sees at most one site banner
  (W06) that staff schedule without a rebuild.
- **An admin** can change a limit, turn a feature off in an incident, force an app update, start
  maintenance, change a rate limit, open a market, edit a catalogue row or a translation, and rotate a
  vendor secret. Production changes that the sources mark for four-eyes go through an approval, every
  change is audited, and no change needs a deploy.
- **The business** has one registry of constants. A value that a person reads or a rule a person meets
  is a `remote_config` key, a `feature_flags` key, a catalogue row, an `i18n_strings` key, an
  entitlement or a CMS field, never a literal in client code.

## 4. API (built first)

Problem responses are RFC 9457 problem+json with a request id [TR §8.1]. Statuses and `reason`
codes are those of [1MM-STD-13](../standards/1MM-STD-13-ERROR-CODES.md): 422 `validation` for
invalid input, 404 `not_found`, 412 `precondition_failed` for a stale `If-Match` [ADM §1.4], 503
`maintenance` with `Retry-After` [WEB W06]. Admin paths are relative to `/admin/v1`; every admin write sends `Idempotency-Key` and
`If-Match`, takes a reason where the permission requires one, and writes one audit row in the same
transaction [ADM §1.2–§1.4].

### 4.3 Rules the API must enforce

1. `GET /v1/config` returns only `remote_config` rows where `is_public` is true [SQL].
2. A `remote_config` value of JSON null is "not set": the API applies the documented safe default and omits the key from the public payload [SQL].
3. A public key change reaches `GET /v1/config` within 60 s [ADM A24].
4. A value outside `min_value`–`max_value` is refused; a value above a database-enforced limit is refused (`intro.voice_max_seconds` ≤ 20, `media.clip_max_seconds` ≤ 30, `trusted_contacts.max` ≤ 3, `groups.max_members` ≤ 500) [ADM A24].
5. In production a change to flags, remote config, rate limits, vendors and markets carries an approved, unused approval for the same permission, table and key; the database refuses it otherwise (`42501`). The API answers the request with 202 and the approval request before any write, so a write that reaches the trigger unapproved is a bug and surfaces as 500 `internal` ([1MM-STD-13](../standards/1MM-STD-13-ERROR-CODES.md) §4.6) [SQL].
6. The approval permission of a `remote_config` change is read from the row's current `permission_key`, so changing the key itself needs approval under the old permission [DD §13B.3].
7. Turning a kill switch **off** needs reason and re-auth only, runs at once, notifies super admins and creates a retrospective review item; turning it on follows the approval rule [ADM A31].
8. A flag is on for a caller when `enabled` and the caller's stable hash is below `rollout_percent`, and `rules` match; a `feature_flag_overrides` row for the member wins [SQL], [DDR B17].
9. `app_versions`: semver format and `latest ≥ min_supported`; the current row per platform is the newest with `effective_at ≤ now()` [ADM A31], [SQL].
10. Version state: below `min_supported` → `required` (no way past); below `latest` → `recommended` (snooze `app.recommended_update_snooze_days`); otherwise `none` [CN], [SQL].
11. A maintenance window is active when `starts_at ≤ now()`, `ends_at` is null or later, `cancelled_at` is null, and the caller's platform is in `platforms` [SQL].
12. While an active window has `read_only`, member write endpoints answer 503 `maintenance` with `Retry-After`; reads keep working [ADM A31].
13. Website maintenance pauses every form endpoint with 503 `maintenance` + `Retry-After`, except the forms in `site_settings.maintenance.exempt_forms` (the W34 safety report) [OD-32], [WEB W06].
14. `GET /public/v1/config` returns at most one banner, by priority incident > maintenance > offer > info; kind `offer` is never returned while `offers.enabled` is off [WEB W06], [OD-01].
15. Rate-limit edits take effect without a deploy [ADM A31].
16. Secrets are never returned or logged; `vendor_settings.settings` refuses secret-like keys at any depth; rotation returns metadata only [ADM A31], [SQL].
17. `POST /jobs/:name/run` is refused for a job that is not `run_now_allowed`; a destructive job can never be run on demand [SQL].
18. A catalogue row that members reference is never deleted; it is deactivated (`is_active = false`). Option-set structure is read-only. A message effect's `min_role` is never below `CLASSIC` [ADM A24].
19. A translation cannot be marked reviewed by its last editor (API check and `i18n_review_not_editor`) [DDR B26].
20. An ICU syntax error blocks save; a value longer than `max_length` is refused; a missing locale falls back to `en` [ADM A25].
21. **Recommendation:** key prefixes name the surface that uses a string (`app.`, `site.`, `admin.`, `n01.`, `ncat.`, `lang.`, `country.` …) so the "Used by" filter needs no new column; the prefixes already in the seeds (`lang.en`, `country.ng`, `n01.title`, `ncat.account`) stay as they are [SQL].
22. Only `en`, `pcm` and `fr` can be app locales (`app_locale` domain); the brand name and the slogan "Don't waste my time." are never translated [SQL], [WEB §3.8].
23. Moving a city to `live` or `beta` needs approval; the response warns when the country has no verified emergency number [ADM A31], [OD-09].
24. Launch seeds are asserted by a test: `offers.enabled` off, `discovery.international` on, Lagos `live`, other Nigerian cities `beta`, every other city `waitlist`, only NG with an emergency number (112) [ADM A31], [OD-01], [OD-09].

| OB1 Recommended    | Dismissible                   | "Not now" snoozes for `app.recommended_update_snooze_days`; snooze stored on the device                                                    |
| OB1 Maintenance    | Blocking with retry           | Retry with backoff; shows `until` and the status-page link; message from `message_key`. `read_only` shows a banner instead of blocking     |
| OB2 Language       | Sheet with radios             | Suggested option from SIM or store country, never GPS; choice saved on the device, applied at once, synced to `users.locale` after sign-in |
| Config unreachable | A0·E offline (MOD-00)         | The app uses the last cached config for flags and limits; a cached `required` state still blocks                                           |

- **Bootstrap client.** One provider fetches config before navigation mounts, caches it, refreshes
  on app resume and every 60 s in the foreground, and exposes `useConfig(key)`, `useFlag(key)` and
  `useTranslator()`. Screens never read a literal limit.
- **Catalogue delivery.** The bundled `packages/i18n` catalogue is the floor; EAS Update ships newer
  catalogues ([1MM-STD-19](../standards/1MM-STD-19-OTA-UPDATES.md)); the runtime overlay follows
  GAP-MOD02-04. `runtime_version` in `app_versions` pins OTA bundles [SQL].
- **Gating and upsell:** none on these screens.
- **Accessibility:** tap targets ≥ 44 × 44 px; real radio controls in OB2; each language shown in its
  own language; text scales to 200% [TR §2.4].
- **Haptics and sound:** `selection` on the OB2 choice; no sound [TR §2.5].
- **Phone and tablet:** OB1 is a centred full-screen state on both; OB2 is a bottom sheet on phones
  and a centred sheet on tablets, per
  [1MM-STD-03](../standards/1MM-STD-03-MOBILE-BUILD-STRATEGY.md).
