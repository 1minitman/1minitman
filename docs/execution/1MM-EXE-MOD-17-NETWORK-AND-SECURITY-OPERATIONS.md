This is the execution plan for the admin network and security dashboard (A32): traffic views, IP
grouping, detections, responses under approval, IP allow and deny lists with their edge sync, the
WAF status page and the security incidents register. Open it before changing how a request is
blocked or limited, and before adding a table that records an IP, a device or a sign-in signal.

## 1. Outcome

- **For a member:** nothing to see. Abuse from one network is limited or blocked without a
  CAPTCHA [TR §13.2], and a block of an abusive range does not need an app release.
- **For an admin:** A32 shows sampled traffic within seconds, aggregates by endpoint, country,
  platform, status class, IP prefix, ASN and user-agent family, detections from configured rules,
  a response queue where every block or limit is approved by a second admin, IP lists that expire
  on time and stay in step with Cloudflare, WAF status and an incidents register with the NDPA
  72-hour clock [ADM A32].
- **For the business:** network history does not depend on Cloudflare's free-plan retention
  [OD-06]; every security response is reasoned, approved and audited [TR §7.1]; a data breach has
  a recorded awareness time and regulator notification [TR §13.4].

## 2. Scope

**In scope**

1. A32 in full: Live, Aggregates, Detections, Responses, IP lists, WAF status, Incidents.
2. The enforcement of `ip_access_rules` for member, public and webhook traffic at the API, and
   the edit path for every scope.
3. Per-IP-prefix rollups (`api_request_ip_rollups`) and the extra sample columns.
4. Jobs `security.detect`, `edge.import`, `ip_rules.sync`, `ip_rollups.purge`.
5. The incident register used by A03 alerts, A07 chain breaks and break-glass closes, and the
   "incident open" answer that MOD-01's early unlock needs [OD-29].

## 4. API (built first)

### 4.1 Endpoints

All are on `/admin/v1` with an admin session [TR §8.2]. Writes carry `Idempotency-Key` and a
reason and write `admin_audit_log` [ADM §1.3], [ADM §1.4]. Problem types follow
[1MM-STD-13](../standards/1MM-STD-13-ERROR-CODES.md): 401 `unauthenticated`, 403 `permission`
(or `reauth_required` when the step-up is stale), 404 `not_found`, 422 `validation`, 409
`illegal_state` or `duplicate`, 412 `precondition_failed`; an approval-gated write answers 202
with `approval_id` and `expires_at`. No analytics events: admin actions are
audited, not tracked.

### 4.3 Rules the API must enforce

1. Viewing needs `network.read`; proposing needs `network.respond` and a reason; applying IP list
   changes needs `security.ip_lists` with approval and re-auth; rate-limit responses need
   `security.rate_limits` with approval; incidents need `security.incidents` and a reason
   [ADM A32], [ADM App. A.8].
2. Every block, limit, challenge or allow-list response is an `admin_approvals` request; the
   requester cannot approve; an approved response is applied and reaches Cloudflare within 60 s
   [ADM A32], [TR §7.1].
3. A deny rule has an expiry no later than 90 days after creation [SQL `ip_deny_expiry_chk`].
4. An expired or removed rule is ignored by the API and removed from Cloudflare by the job
   [ADM A32].
5. Removing a live deny rule during an incident is allowed with approval [ADM A32].
6. No CAPTCHA option exists. `challenge` is accepted only for website and web-app routes
   [ADM App. D AD-19], [TR §13.2].
7. A detection becomes `responded` only with `response_approval_id`; it is unique per rule,
   subject and window start, so a re-run does not duplicate it [SQL].
8. A rule whose `security.detect.*` value is `null` is not evaluated [SQL seed description].
9. An edit that would exclude the IP of every live super-admin session from the `admin` or `all`
   scope is refused unless confirmed by typed confirmation, and still needs approval [ADM A03],
   [ADM A32].
10. Samples and IP rollups store prefixes only (/24 IPv4, /48 IPv6); user ids are hashed; query
    strings are never recorded [SQL], [TR §14].
11. The Live view says it is sampled and shows a request within 5 s [ADM A32].
12. A `data_breach` incident starts the 72-hour clock at `aware_at`; the clock stops at
    `regulator_notified_at` [SQL], [TR §13.4].
13. Incident status needs its timestamp: `contained_at` from `contained`, `resolved_at` from
    `resolved` [SQL].
14. An incident can be opened from a detection, an A03 anomaly alert, an A07 chain break or by
    hand; the source row keeps the `incident_id` [ADM A32], [SQL].
15. While an incident linked to a locked admin is open, an early unlock needs a second admin
    [OD-29]. This module answers "is it open". **Recommendation:** open means status `open` or
    `contained`, the same set as `idx_incidents_open`.
16. The console changes nothing at Cloudflare except IP Access Rules [ADM A32].
17. A production change to `rate_limit_policies` without an approved approval is refused by the
    database [SQL `trg_rlp_approval`].
18. When Cloudflare is unreachable the WAF page shows the last known status with its time; sync
    drift is shown as a warning, never hidden [ADM A32].
