This is the execution plan for the content management system inside the admin console and for the
public website it feeds. Open it before building any `/admin/v1/cms/*` endpoint, any A28 or A29
view, the `/public/v1` content and form endpoints listed here, the publish pipeline, or any owned
website module. Section 3.2 maps every website field to the table column and the admin screen that
edits it; use it to check that nothing on the site is hard-coded.

## 1. Outcome

| For          | What is true when this module is done                                                                                                                                                                                                                                                                                                                                                                  |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A visitor    | Reads an information-only site in en, pcm or fr, light or dark, that loads within the budgets on a mid-range phone; reaches the right app store through "Get the app", the QR or `/get`; joins the waitlist for a city that is not live; applies for a job; sends an investor enquiry. There is no sign-in, checkout or offer [OD-15], [OD-01].                                                        |
| An admin     | Builds any page from blocks, previews it in both themes and three locales, sends it through review, publishes or schedules it, and sees it live within 5 minutes; manages media with licence and consent records, stories, FAQ, press, careers, investor documents and the journal; works the contact inbox, the waitlist and beta invites, applications and the newsletter list [ADM A28], [ADM A29]. |
| The business | Every word, image and setting on `1minitman.com` is changed in the admin console with no deploy, behind a two-person rule and a validator that blocks banned terms, unsourced numbers and unlicensed media [WEB §6], [OD-21].                                                                                                                                                                          |

## 4. API (built first)

### 4.1 Endpoints

Admin paths are relative to `/admin/v1`; each write needs a reason where the permission requires
one, sends `Idempotency-Key`, uses `If-Match` for edits (412 on conflict) and writes the audit
event shown [ADM §1.2], [ADM §1.3], [ADM A28]. Problem types follow
[1MM-STD-13](../standards/1MM-STD-13-ERROR-CODES.md) [ruling R17]: a bare 422 is `validation`, 404
`not_found`, 403 `permission`, 412 `precondition_failed`, 429 `rate_limited`, 503 `maintenance`,
and a 409 is `illegal_state` or `duplicate` unless a code is named. The public form rows quote the
error names of [WEB §5.10] in brackets (`city_live`, `job_closed`, `token_invalid` and the like)
after the registered `reason` each maps to in 1MM-STD-13 §4.5, and a wrong type or size on upload is 415 `unsupported_media_type` or
413 `payload_too_large`. Server-side event names are from
[WEB §3.11].

### 4.3 Rules the API must enforce

1. The website reads only published content: the snapshot named by `live_revision_id`. A newer draft never leaks [DD §13B.2].
2. Workflow transitions are those of `content_workflow_guard()`; the approver is not the last editor; a scheduled item is not published early [DD §13A.2].
3. `pcm` and `fr` rows publish only with a native review, or are marked `fallback_to_en`; `en` required fields are complete [WEB §6.4-1].
4. Character limits per block field; no raw HTML; links are https or internal references [WEB §6.4-2].
5. At most two `ink_band` sections per page and exactly one h1 source (`page_header` or `hero_promise`) [WEB §6.4-3].
6. Media needs alt text or the decorative flag, and a licence reference; an identifiable real person needs `consent_ref`, a model needs `model_release_ref`; expiry unpublishes dependent blocks [WEB §6.4-4].
7. Numbers in `proof_stats`, `company_facts` and `cities.stats` need `source`, `as_of` and approver; a value older than 90 days is hidden at the next build [WEB §6.4-5].
8. A story publishes only with both partners confirmed, `consent_status = 'active'` and `consent_ref`; withdrawal unpublishes everywhere within 24 h and the URL answers 410; no illustration or stock image on a story [WEB §6.4-6], [WEB W27].
9. Pages with prices, legal wrappers and investor pages need a `content.review_legal` approver; safety pages, safety-category journal articles and emergency numbers need `content.review_safety` [ADM A28].
10. While `offers.enabled` is false, no offer block, banner kind, teaser or terms page can be saved as publishable; no prize draw, lottery or sweepstake content ever [WEB §6.4-7], [OD-01], [OD-10].
11. Banned-terms check on every text field: the retired plan name and price, a subscription wording for the Black Badge, "renews" next to Black Badge, any price not in `prices`, "live phone check", and any daily-cap or intro-window number that differs from config. [WEB §6.4-8]. **Recommendation:** the API validator and `pnpm check:banned-terms` share one term list.
12. A job publishes only with `closes_at`; closing removes its `JobPosting` data [WEB §6.4-9].
13. A slug change on a published item writes a 301; chains and loops are refused [WEB §6.4-10], [SQL].
14. Site settings `maintenance` and `emergency_numbers` change in production only with an approval; no emergency number is published without `verified_by` and `verified_at` [SQL], [WEB W21].
15. Member photos never enter `media_library` [ADM A29].
16. A coverage item publishes only with a working https URL (`link_status`), and shows a logo only with `logo_permission` [SQL], [WEB W29].
17. An investor document marked `gated` has no public URL; access is a time-limited signed link from an approved grant, logged; no figure is published without `finance_signoff_by` [WEB W31], [SQL].
18. A waitlist entry is stored as confirmed only after double opt-in; one entry per identifier per city; a duplicate returns the same message; a live city returns `city_live`; no queue position is ever returned [WEB W25].
19. A beta invite is a single-use code stored hashed; sending moves the entry to `invited` [DD §13].
20. One application per email and job in 30 days; a CV opens only by signed URL after a reason, when the upload is `clean`; no automatic rejection email [WEB W30], [WEB §5.4].
21. `/get` sets no cookie and stores no IP; it logs only the aggregate dimensions of `web_redirects_daily` [WEB §5.1].
22. Every public form here uses MOD-14's pipeline and answers 503 `maintenance` with `Retry-After` during maintenance [WEB W38].
23. The plans blocks never accept a typed price; values come from `GET /public/v1/plans` [WEB W12].
