**What this document is for and when to open it.** It is the build plan for a member's own profile:
the profile screen, editing, photos and clips, the media pipeline to Cloudflare R2, prompts, the
Premium and Gold profile-enrichment steps, and the admin queue that moderates media and prompts.
Open it before writing any profile, media or prompt code, and when another module needs to upload
a file or read a profile field.

## 1. Outcome

- **Member.** A member sees their profile (D14), edits bio, nickname and intention (PM3), manages
  photos and clips within their plan's caps (PM1, PM2), answers up to 3 prompts by text or voice
  (PM8), and completes the lifestyle, career, partner-preference and media steps of the Premium and
  Gold flows (P1–P4, GD4) up to the payment step. Every photo and clip goes public only after the
  face match and moderation pass [SQL `media_assets` CHECK].
- **Admin.** A reviewer with `media.moderate` works one queue (A13) for flagged media, face-match
  reviews, prompts and group avatars, with every decision audited [ADM A13].
- **Business.** One media pipeline serves every later module (badge photos, voice intros, chat media,
  evidence, group avatars). No profile limit, option list, prompt or rejection message is hard-coded.

### 4.2 Realtime, jobs and webhooks

- **Jobs.** The shared stale-claim release job (section 4.1; rulings R16 and R29).

  moderation (nudity, violence, text, QR); colour-filter check; then quarantine → active or
  rejected. `media.transcribe` (on voice upload): transcript for moderation. `retention.purge`
  (daily): purge assets past `purge_after` and prompt answers removed more than 30 days ago
  [TR §11], [TR §16.1].
- **Realtime.** The member socket has no media event [TR §8.3] (GAP-MOD04-01). The admin stream
  uses `queue.counts` and `case.claimed` [ADM §1.6].
- **Webhooks.** None. The face-match and moderation providers are not named by any source →
  GAP-MOD04-04.

### 4.3 Rules the API must enforce

1. Profile edits use optimistic concurrency: `If-Match` must equal `profiles.version`; a stale
   value returns 412 [TR §8.1].
2. Nickname: 2–20 characters; not 5 or more digits, no `@`, no links; not a reserved name; not held
   by another member in `nickname_history`; one change per `nickname.change_cooldown_days`; the old
   name is held `nickname.hold_days` [SQL], [DDR M37], [TR §2.2].
3. Bio, job title and prompt text pass the contact-detail filter on the server; the client runs
   the same rule live [TR §5.1], [TR §13.4].
4. Sensitive option sets (`faith`, `faith_practice`, `genotype`) are written only when the matching
   consent is current, and are never returned to any other member or to the admin console
   [TR §16.2], [ADM A10].
5. At most 6 languages; "prefer not to say" is always accepted [DDR M49], [UF §9.1].
6. Upload URLs are refused above the member's `media.photos_max` / `media.clips_max` with
   `403 {reason:"entitlement"}` and the D15 upsell target [TR §8.1], [TR §9].
7. Upload URLs are refused for photos and clips when biometric consent is withdrawn [TR §16.2].
8. Every upload goes to `media-quarantine`; the app never holds cloud keys [TR §5.3].
9. A photo or clip becomes `active` only when `face_match` is `match` or `not_required` and
   `moderation_status = 'approved'`; a photo with a colour filter never becomes active [SQL].
10. A face mismatch is never added to a slot; the member may ask for a human review once per asset
    [CN], [UF §15.18].
11. The main photo is a photo in slot 1; it cannot be deleted until another photo is main [SQL],
    [TR §8.2].
12. Delete sets `deleted_at` and `purge_after` = now + `media.soft_delete_days`; restore works only
    within `media.delete_undo_seconds` [UF §15.18].
13. Clips ≤ `media.clip_max_seconds`; voice ≤ `intro.voice_max_seconds`; the schema ceilings (30 s,
    20 s) hold even if config is set higher [SQL].
14. At most 3 live prompt answers, one per prompt, one per position; an answer is text or voice,
    never both [SQL].
15. Voice prompts are transcribed and moderated; prompts are open to every plan [UF §15.18], [UF §12 D64].
16. Admin approve: sets `moderation_status = 'approved'`; when `face_match = 'manual_review'` the
    reviewer must also set match or no match; writes `moderation_actions` (`approve_media`)
    [ADM A13].
17. Admin reject: `moderation_status = 'rejected'`, `status = 'rejected'`, reason code from
    `decision_reasons`; the member is told with the reason's `member_message_key` [ADM A13].
18. Admin hide: `status = 'hidden'`, `profile_media.hidden_reason = 'moderation'`. A main photo
    cannot be hidden alone: the profile is hidden instead (`profiles.is_hidden` with
    `hidden_reason = 'restricted'`) until a new main photo passes [ADM A13].
19. Prompt removal by an admin sets `removed_at` with no Undo and notifies the member; admins never
    edit a member's words [ADM A13], [ADM A11].
20. Bulk approve or reject: media only, at most 50, one `moderation_actions` row per item; voice
    prompts are never bulk-decided [ADM A13].
21. A row outside the admin's scope returns 404, never 403 [ADM §1.1].
